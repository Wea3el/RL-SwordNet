# ASE 直刺与上拨挡的双机物理测试

本页是早期完整片段的 v1 对照，保留原规则和失败结果，不是新五技能 A1 库的验收或 self-play 成果。当前双 self-play 研究范围见[项目框架](plan1_zh.md)，最新整段剑身规则及候选状态见[技能验证](skill_validation_zh.md)。

完整 ASE 直刺经过统一空间校准后，已经能驱动现有机械臂命中固定目标。上拨挡能够映射和播放，但本轮已完成的共用摆位及角色适配试验尚未得到合格的物理防守。不能把“姿态拟合成功”或“碰到对手的剑”当成“成功挡住进攻”。

## 数据与执行方式

来源固定为 ASE 提交 `6f9b4f1f289603eee6a4f45d082bc6e6d83fecec` 的 `RL_Avatar_Atk_Stab_Motion.npy` 和 `RL_Avatar_Sword_ParryUp_Motion.npy`。读取前检查文件大小及 SHA256，再使用受限数值转换器解析，不执行不受限 pickle。来源声明限定非商业用途，测试不修改或重新发布源动作文件。

保留直刺全部 128 个源帧、上拨挡全部 58 个源帧，每个源间隔加插值后分别得到 509 和 229 个目标。使用原模型实际夹持点、剑尖和 7 个关节求连续 IK，不直接复制人形关节角。手部位移使用既有 0.5 适配比例；机械臂与 1.080 m 竹剑的几何尺寸不缩放。

两段源动作本身都包含回收，执行程序各播放一遍，前后另接明确标记的警戒位过渡；不会把整段完整动作再倒放一遍冒充源动作。每个关节采样区间伸长到满足 0.35 rad/s 目标速度的整数控制周期，保留所有样本，但不保留源动画的速度和节奏。这是完整几何路径的物理测试，不是原速动作复现，也不是训练好的模仿学习策略。

## 与人工动作相同的判定标准

仍使用两台地面固定机械臂，相距 1.75 m；固定靶心为防守方朝内 0.32 m、高 1.05 m。有效计分半径保持 70 mm。原 CAD、竹剑、夹具、增益及调试力矩上限均不改，关节角范围仍是假设的 ±π；实际速度超过 2 rad/s、跟踪误差超过 0.5 rad、非法代理接触或数值警告等会使试验无效。

每个条件分别运行“不防守”和“播放上拨挡”。二者初始状态及攻击方的全部控制目标必须相同，接触或命中不会改变程序。成功要求无防守原本会命中、防守后完整观察窗口不命中、首次实际剑刃接触发生在无防守命中之前。

为了不把人工连接算成 ASE 的功劳，另要求无防守的首次命中发生在原生 Stab 窗口内，首次剑刃接触发生在双方原生动作窗口的交集中，并满足原生窗口内的接触冲量阈值。人工警戒位连接中的接触仍会记录，但不能据此声称 ASE 防守成功。

## 原始映射与共用摆位校准

原始任务空间映射沿用单臂展示设置：共同绕 Z 旋转 30°，中立夹持点 `[0.05,-0.45,1.05]` m。这是保留原任务空间映射、重新求解 IK 的基线，不保证与旧求解结果逐项相同。

基线双机实际运行约 21.01 s，两段动作可播放，没有非法接触，但无防守的直刺距靶心最近仍约 345.98 mm，且没有剑间接触。正确解释是摆位没有构成有效进攻，不能据此评价防守或否定整个数据集。

共用摆位校准将直刺源帧 52、相位约 0.40945 的最大前伸剑尖对齐固定靶心，仍保持共同 30° 旋转和 0.5 位移比例。两动作使用同一中立夹持点 `[0.240577,-0.373985,0.722142]` m，并选择通过碰撞检查的连续 IK 分支。没有单帧挪动、截取片段、缩小靶区或提高力矩。

校准后的两个完整动作和四段警戒位连接均通过静态检查。物理测试中，无防守的直刺约 9.908 s 命中，最近剑尖距靶心约 5.78 mm，首次命中位于源 Stab 窗口内。

对上拨挡测试了整体延迟 0、3、4.5、5、5.25、5.5、5.75、6、6.5、7.5、9 s，共 11 个条件；全部完成，但没有一个条件保护目标。部分条件存在原生动作中的真实剑刃接触：例如延迟 5 s 峰值约 22.18 N，依然失守；延迟 5.5 s 的最近距靶心约 58.86 mm，仍小于固定 70 mm 阈值，因此也是失败。

这些是该机械模型、该共同变换和所测时序下的失败，不证明其他 ASE 防守或所有映射都不可能成功。

## 防守角色的完整动作适配

另一组试验保留同一校准后的直刺，单独调整完整 ParryUp 的固定任务空间变换：将源帧 16、相位约 0.28070 的剑轴对齐机械臂坐标的 +Z，夹持点对齐 `[0.5,0,0.75]` m。整段防守使用同一个旋转和平移，所有源帧保留。这个变换将原上方向倾斜约 60.16°，应称“角色专用的整段重定向”，不是保留人体上方向的小幅姿态修正。

| 延迟 | 实际物理结果 | 判定 |
| --- | --- | --- |
| 2.5 s | 没有有效碰剑，进攻命中 | 防守失败 |
| 3 s | 已出现接触、当时未命中，但约 10.47 s 因关节跟踪误差超过 0.5 rad 中止 | 试验无效，不能算成功 |
| 3.5 s | 当时未命中，但同样因跟踪误差超限中止 | 试验无效，不能算成功 |
| 4 s | 完整播放，有接触，进攻仍命中 | 防守失败 |

这一分支还接近假设的 −π 关节限位。后续求解增加关节角余量，并记录软件限位约束力，避免依靠尚未识别的硬挡块“辅助挡住”。原探索记录保留，不会因看起来将剑拨开就改记成功。新的优化候选仍须完整通过姿态、过渡和真实物理检查。

最后一轮将 IK 范围向内收紧 0.05 rad，仅改变求解器可用范围，不改变场景实际限位；同时实际播放检查假设关节限位是否提供超过 0.1 Nm 的约束力。有限的四个候选分别改变额外朝向 −15°、+15°，提高关键握点至 0.9 m，或把其局部 X 改为 0.55 m。三者到达预设的余量边界，未进入该轮更严格的物理测试。提高握点的候选通过静态检查，但三个启动时机均未形成有效成对试验：无防守回合超速，防守回合发生剑刃与护手的非法接触。该轮未继续扩大搜索，也没有为获得成功而放宽跟踪、速度、碰撞或力矩阈值。

即使某个角色专用版本通过，它与进攻使用不同警戒位和变换，也不能直接称统一的 `0/1/2` 技能库；技能间的切换仍须验证。

## 当前选择

ASE Stab 可以作为经过校准、重定时的进攻参考；ASE ParryUp 目前不应作为已经可靠的防守技能交给 PPO。考虑项目工期，可先保留人工直刺与侧拨的已验证组合，让 A2 学习发动时机；ASE 防守作为独立适配实验保留，避免训练依赖一个本身尚未证明可防守的动作。

如果进一步抽取少量 ASE 关键姿态、插值或修改中间轨迹，可以降低运动复杂度，但必须改称“ASE 派生的关键姿态技能”，重新做同样的物理验证。它不再等同于完整原始动作或纯模仿学习。

## 复现与证据

原始映射测试不需要联网下载，读取本地已校验来源；输出目录必须是新的：

```bash
python -m sim.ase_duel --output outputs/ase_original_new
python -m sim.ase_duel --output outputs/ase_calibrated_new --geometry config/ase_duel_shared.json --delays 0 3 4.5 5 5.25 5.5 5.75 6 6.5 7.5 9
python -m unittest discover -s tests -v
```

`--config` 可提供目标速度及启动延迟；`--delays`、`--speed-scales` 或调用 `run_experiment(..., cases=[...])` 可复现显式条件。默认无成功防守时 CLI 返回非零，不表示源文件损坏或物理引擎没有运行。单臂预检查失败会保存完整失败报告并拒绝进入双机物理测试。

主要本地证据目录：

- `outputs/ase_duel_original_round1`：保留原映射的物理基线。
- `outputs/ase_duel_shared_calibrated_round1`、`outputs/ase_duel_shared_timing_round2`、`outputs/ase_duel_shared_timing_round3`：共用摆位校准及全部 11 个时序。
- `outputs/ase_duel_role_adapted_round1`：角色专用整段适配的四个物理条件，包含两次无效试验。
- `outputs/ase_inspection`：全部静态候选、失败帧、映射参数和几何筛查，不是物理成功证据。
- `outputs/ase_inspection/final_bounded_four`：增加限位余量后的四个候选及三个无效物理条件。
- `outputs/ase_duel_shared_frozen_final`：当前源码和限位力检查下复测的共用映射、延迟 5.5 s 条件。

`outputs/ase_duel_shared_timing_round2/ase_stab_parryup_excerpt.mp4` 是 7 至 12 秒的真实状态回放节选，显示碰剑后仍失守的情况，不是成功演示。可用同一回放工具重新生成：

```bash
MUJOCO_GL=egl python -m sim.manual_duel_replay --run outputs/ase_duel_shared_timing_round2 --case delay_5p5 --output outputs/ase_duel_shared_timing_round2/new_excerpt.mp4 --fps 8 --start-s 7 --end-s 12 --azimuth 125
```

各物理条件保存同一场景 XML、参数、源文件与实现哈希，以及实际关节角、速度、控制目标、执行器力矩和剑刃力日志。输出被 Git 忽略，不能把本地结果当作 GitHub 已上传附件。几何和时钟都会随 IK 适配变化；这里比较的是整个重定向、重定时程序，不能把差异单独归因于 pose。
