# A1 新限位与连续动作修订

现有五技能 v5 不满足本次完整需求，也不满足新确认的关节角边界。修订分成三层：在真实角度范围内重建姿态，生成无强制长停顿的连续过渡，再验收实际跟踪与攻防。旧 v5 与 checkpoint 保留，不能直接裁剪关节角后继续训练。

## 已确认的关节范围

用户确认截图表与当前 CAD／MuJoCo 同名、同零位、同正方向。

| 关节 | 下界 | 上界 |
| --- | --- | --- |
| J0 | 0° | 360° |
| J1 | 0° | 180° |
| J2 | 0° | 360° |
| J3 | −20° | 120° |
| J4 | 0° | 360° |
| J5 | 15° | 145° |
| J6 | −90° | 90° |

`sim.joint_constraints` 检查未经折返的原始角度，不逐帧取模。0～360° 也有端点，不能当无限旋转关节。`sim.limited_model` 在物理开始前将这些范围应用到关节与 position actuator 的控制范围，并使用合法初态；J5 下限是 15°，不能再用全零关节姿态初始化。源几何、惯性、碰撞掩码和原调试力矩上限保持不变。

截图中的电机 RPM、减速比和 100% 效率理论输出力矩本轮不替代已有力矩模型。本次任务仅落实角度限制；这不等于已完成电机速度、扭矩或实机安全标定。

原 v5 Guard 为 `[52.149, −68.617, −117.803, −141.181, 21.232, 30.908, −7.015]°`，其中 J1、J2、J3 越界。对完整多项式的审计显示五技能均有越界，不只是个别关键帧。旧原生轨迹的相关关节也越新界限；此前攻防通过只属于旧假设。

## 文字需求的解释与覆盖

坐标约定为前方 +X、机器人自身左侧 +Y、上方 +Z。躯干／头部仅作为虚拟位置参考，不重新加入实体躯干。具体米制坐标是根据文字建立的可调整候选，不是队友给出的测量值。Plow right 重复写成左侧，按左右镜像解释；Kron 未规定剑轴，因此先只验收握点位置，不自行断言其剑轴正确。

| 需求 | 原 v5 的对应程度 | 新约束候选当前结果 |
| --- | --- | --- |
| Roof 左／右，高位且指向上 | 没有对应的命名高位守势；旧直立侧挡不等同 Roof | 当前推定坐标与上指轴未在限定求解预算内同时满足，保留失败结果 |
| Fools 左／右，低位且指向下 | 无专门守势 | 两个静态目标可达；右侧至 Long Point 的连续连接仍失败 |
| Plow 左／右，低位且向前 | 原斜向 Guard 不等同左右 Plow | 两个静态目标与 Long Point 连接可用作运动学候选 |
| Ox 左／右，高位且向前 | 无专门守势 | 两个静态目标与 Long Point 连接可用作运动学候选 |
| Long Point，中央水平向前 | 旧 Guard 剑轴向上约 32°，不满足严格水平 | 新水平候选可达，作为连接点 |
| Kron，中央头顶上方 | 无对应守势 | 握点候选可达并可连接，剑轴仍需进一步规定 |

这里的“可达”表示受限 IK 与所采样的代理几何检查通过，不是已能稳定保持或有效格挡。当前 8/10 静态候选通过；Roof 的失败不证明所有可能的 Roof 位置都不可达，只说明目前显式坐标与方向组合未通过。

另保持 Roof 的高度 1.10 m、左右偏移 ±0.25 m 和正上剑轴，只将前向位置分别调到 0.45、0.55、0.65 m，六个候选仍全部失败。最佳组合仍有约 56 mm 握点误差与约 22° 剑轴误差，因此不能将前移位置当作已完成的修复。

五类动态切击按起点—Long Point—终点解释。文字允许“任意高位”起刀，因此现阶段使用 Ox 作为斜切高位端，而不是把尚未通过的 Roof 强行放入路径。`velocity > 1` 没有单位或指定测量点，不擅自解释成关节 rad/s 或剑尖 m/s；记录速度，暂不宣布满足该项。

## 不连贯的实际原因

旧 v5 的位置、速度、加速度接缝已经在数值上连续。问题是时序和动作组织：

- 原 ASE 关键帧间被重新做成接近静止到静止的片段，再慢放四倍，削弱了原动作节拍。
- Stab 与 Slash 分别长 27.60 s、28.72 s；人工 Left、Right 分别长 30 s、25 s，含 16 s、8 s 保持。
- 每招都要回到共同 Guard 才允许下一招；执行期间不能切换。稳定确认通常只约 0.1 s，不是主要停顿来源。

因此继续做 PPO 不能直接修复这种长宏动作。也不能整体粗暴加速：原参考速度已不低，缩短时间会放大加速度与跟踪误差。

## 已实现的修改与当前边界

新增 `C2JointSpline` 将多路点作为一条轨迹处理，中间同向运动保留共享速度，不每到一个点都归零；只有反向或显式保持需要停下。其 Bézier 控制点保证整个插值在相邻关节端点范围内，不只检查离散采样。

`sim.a1_flow` 将静态守势和连续路径分开，通过逐点 warm-start IK 构造 Long Point 与各守势的连接，再组合切击；不强制每招回旧 Guard，不嵌入 8／16 s 保持。保留旧失败和新路径的全部失败点。该结构尚未接入原五动作网络，不能把它当作已训练新版 A1。

同一剑位姿可能有多个关节解。当前 Fools left 的独立静态解与连续路径端点最大相差约 5.01 rad，不能在两者间跳转。新版报告将独立静态拟合保留在 `poses`，把真正用于停留和衔接的唯一关节状态放在 `graph_nodes`；每个节点必须来自同一个精确 Long Point 状态出发、通过整条连续参考检查的连接端点。缺少连接的静态姿态不进入该图。

当前新版连接中，右上到左下、左下到右上、Kron 到 Long Point 三条通过整条参考角度范围与 10 ms 代理几何采样。另两条斜切仍受 Fools right 连接失败影响，不进入可用集合。原先简单拼接合法端点时曾出现约 0.10 m 自穿透，已保留该失败并改为检查完整连接，不能靠“端点都合法”放行。

两条斜切通过 Long Point 时参考剑尖速度约 0.067 m/s，峰值约 1.095 m/s。虽然没有强制静止，中心段仍明显减速；数学连续不等于已经恢复自然挥剑节奏，后续还需调整任务空间轨迹及节拍。

右上到左下另做了单次真实动力学检查：4 s 运动加 0.5 s 观察，RK4／1 ms、原力矩上限不变。实际关节没有越新边界，未出现代理穿透，最大关节跟踪误差约 0.263 rad。这说明该条运动能在当前模型执行，不证明它准确复制专家动作、能命中／格挡，或已满足 `velocity > 1`。测试直接初始化在起始姿态，进入该姿态的路径另验。

## 本地复现与证据

```bash
python -m sim.a1_flow --output outputs/a1_named_flow_new
python -m unittest tests.test_joint_constraints tests.test_limited_model tests.test_motion_spline tests.test_a1_flow -q
```

- `outputs/a1_pose_requirements_probe_v1/`：第一组文字解释的全部固定目标结果。
- `outputs/a1_named_flow_v1/`：直接拼接端点的成功与穿透失败。
- `outputs/a1_named_flow_connected_v2/`：向前外绕连接的失败记录。
- `outputs/a1_named_flow_connected_v3/`：不外绕连接的前一版参考轨迹及失败点。
- `outputs/a1_named_flow_connected_v4/`：当前版本，额外检查所有连接的连续参考，并明确唯一 `graph_nodes`；三条切击与 v3 的数值轨迹一致。
- `outputs/a1_roof_forward_probe_v1/`：保持高位和正上剑轴的六次前移探针，全部失败。
- `outputs/a1_flow_native_down_right_v1/`：单次原生跟踪检查，非对打或训练。

实际运行视频：`outputs/a1_flow_native_down_right_v1/native_continuous_cut.mp4`，来自保存的物理轨迹，不是用参考关节角直接播放的动画。

本轮完整代码回归共 440 项测试通过。该结果验证代码与接口，不替代上述实际轨迹或攻防验收。

后续双机检查已建立一组在新限位下通过完整窗口的攻击／格挡正例，并保留晚格挡、错误方向和入口失败等反例，见[双机攻防验证](a1_native_combat_zh.md)。该组合仍有不同准备姿态，不能直接当成同一个 agent 的可选技能。接下来先验收攻守衔接和观测触发，再扩展方向覆盖；Fools right 的合法连接、Roof 的可达位置／方向仍属未解决项。接入新动作图需重新定义 action mask 与快照兼容性，旧五动作 checkpoint 不直接继承。
