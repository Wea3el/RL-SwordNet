# Plan 1：小型数据技能库与 PPO 自博弈调度

方案日期：2026-11-21。初期报告截止：2026-11-22；最终报告截止：2026-12-03。

项目仓库：[RL-SwordNet](https://github.com/Wea3el/RL-SwordNet)。本方案对应 `plan1` 分支的研究范围；文中的训练、对战和验收项目属于计划，除“现有证据”部分外，不代表已经完成。

## 1. 目标与范围调整

在 MuJoCo 中放置两台固定底座、各持一把 shinai 的机械臂，用一个经过验证的小型技能库实现基本攻击与防守，再研究学习到的技能调度是否优于固定调度。

本方案明确将此前“数据模仿学习模型 vs 从零训练的 RL 模型”的设想，收敛为：**数据参考技能的脚本调度策略 vs 使用同一技能库的 PPO 自博弈调度策略**。双方共享相同的运动能力，主要比较选技与时机，而不是比较两套不同低层控制器，也不声称是纯 BC 与纯 RL 的对照实验。

这是为 12 月 3 日前获得可复现攻防结果而选择的最小主线。Germanic 历史姿态、额外斩击技能、行为克隆（BC）、连续动作生成和实机迁移均为后续扩展；不从零搭建 AMP、GAIL、多源动作融合或视觉系统。

研究问题是：在相同技能、观测、执行约束和计分规则下，PPO 历史对手池自博弈能否改善对战结果，并适应未用于训练的攻击时序？不预设学习策略一定获胜。

## 2. 数据与三项候选技能

仅使用 NVIDIA ASE 仓库中的 Reallusion sword-and-shield 动作来源，不同时引入 Touché、CMU 或 NUS，以减少格式、骨架和标定差异。本项目使用其中的动作参考，**不是复现 ASE 论文的完整算法或直接使用其预训练策略**。

| 技能 | 数据来源与功能 | 当前边界 |
| --- | --- | --- |
| Guard | 从同源参考动作选定可达的持剑姿态，保持或平滑回到该姿态 | 姿态、持续时间和过渡仍须验收，不等于已有独立 Guard 动作通过测试 |
| Stab | `RL_Avatar_Atk_Stab_Motion.npy`，候选刺击动作 | 已有数据解析和局部几何诊断，尚不是生产可执行轨迹 |
| ParryUp | `RL_Avatar_Sword_ParryUp_Motion.npy`，候选上方拨挡动作 | 文件属于 sword parry 而非 shield block；能否挡住本场景来剑仍待接触实验 |

源数据是单个人形角色及其刚性剑、盾的动画，不包含同步对手状态、专家选技标签、真实接触结果或胜负标签。因此可以提供低层动作参考，但不能直接当成反应式对战专家数据。只提取右手与剑的几何，不把左盾动作或步法直接搬到机械臂上。技能名称也不替代对片段内容与动作阶段的人工检查。

ASE 源剑的骨架几何不是本项目 shinai：其手到剑节点约为 0.74 m，而本项目需按实物握点与尺寸重新构建。不能将源剑节点未经变换就称为本机器人剑尖。

## 3. 分层控制结构

控制链为：

`关节与对手状态 → 脚本/PPO 选择技能 → 固定离线关节轨迹 → 原生 position actuators → MuJoCo 动力学`

低层不增加新的学习模型，也不单独模拟电机的电磁、驱动器或详细传动结构；沿用已有 position actuators，但必须配置明确的关节窗口、目标变化率和输出力矩上限。这些上限在拿到实机数据前只能称为仿真假设。

离线使用 IK 将工具空间参考转成 J0–J6 轨迹。高层初期只输出 `Guard / Stab / ParryUp`，不同时学习关节力矩、IK、技能形状和任意速度，以控制工作量。此前 Cartesian policy → Pinocchio IK 的构想，在本方案中收敛为**离线工具空间重定向，高层离散选技**；在线 Pinocchio 不是主线依赖。如后续使用 Pinocchio，必须先与 MuJoCo 核对 FK、关节顺序与工具坐标系。

不通过逐帧覆盖 `qpos` 执行动作。轨迹是控制目标，实际关节仍由积分、执行器力矩、重力和接触共同决定。切换采用固定决策窗口和执行状态机；初期仅在允许的技能边界选技，必要时先平滑回 Guard，避免任意打断导致跳变。决策窗口尽量统一；若采用不等时长宏动作，需正确累计窗口内奖励并按持续时间处理折扣。

## 4. 离线轨迹构建与验收

1. 校验下载文件 SHA-256，以受限转换器解析数据，不对不可信文件直接使用可执行的 pickle 反序列化。导出只含数值数组的中间文件，并记录单位、帧率、四元数约定和骨架结构。
2. 独立 FK 得到源手部握点代理与剑轴；移除 root 平移以取消步法，固定每段的坐标变换。取消平移不等于消除了躯干转动，也不是物理上复现人体步法。
3. 依据实际夹具定义 `end_effector_block → grip → tip` 的固定变换。当前末端 body 原点并不是已标定握点，局部 +X / +Z 剑轴假设需由装配信息替换。
4. 在机器人可用工作空间中统一放置参考动作，记录平移、旋转和位移幅度缩放。若采用 0.5 位移缩放，应称为动作适配，而非原始动作精确复现。评估前冻结这些参数，不用测试对战结果反复调参。
5. 求连续且受限的 IK。第一阶段可检查握点三维位置与剑轴二维方向，但仍须选定平滑的轴向旋转与冗余关节解；5D 可达不代表夹具姿态或整条机械臂无碰撞。
6. 对全部保留帧及连接段检查关节跳变、速度、加速度、限位和自碰撞；插值、减速后重新检查，而非只检查稀疏关键帧。不得通过删除失败帧后直接拼接来制造可执行轨迹。
7. 单臂有限力矩慢放，再加入剑与接触，记录实际跟踪误差、速度、力矩和警告。Stab、ParryUp、Guard 及所有允许的技能过渡均通过后，才接入双机训练。

具体阈值写入配置并随报告保存。未知机械限位不能用假想 ±180° 替代实机数据；若只能在明确的仿真假设下完成，应如实限定最终结论。

## 5. 双机环境、状态与规则

两台机械臂底座固定，剑固定安装在握把处，不增加独立的自由剑或抓握自由度。双方底座间距、朝向、初始姿态和目标区域在场景配置中明确记录。

无视觉阶段直接读取仿真关节位置/速度，并使用模拟器给出的对手剑、目标相对位置与速度。自身编码器不能观测对手；这里采用的是理想仿真状态观测，不是“仅有编码器便能完成真实对战”。两类策略使用相同可见信息，均不读取对手未来轨迹、隐藏技能标签或未来命中结果。

先采用简化、可解释的接触模型：机器人与剑使用适当的简化碰撞几何，定义允许的剑剑接触、有效目标触碰和不允许的机械臂/底座接触。仅有完整视觉 mesh 不等于已有正确碰撞模型。目标碰撞体、几何容差、有效命中阶段和去重窗口均写入规则。

初期建议采用单次有效得分即结束或固定短回合：命中有效目标得分、被命中失分，同时记录平局。一次持续接触不能每个物理步重复得分。数值发散、越界、超限或非法接触分别记录为失败，不与正常胜负混为一类。每次 reset 清理关节速度、技能相位、接触去重和计分状态，并验证初始场景没有穿模。

## 6. 基线、PPO 与自博弈

三类调度器共用同一冻结技能库、状态机、速度和力矩约束：

- **随机选技基线**：在合法决策时刻随机选技能，而非向关节直接注入无界噪声；记录随机种子与分布。
- **数据脚本基线**：使用简单、固定、可复现的进攻/防守时序或阈值规则调度技能。它不是从数据学到的专家战术。
- **PPO 调度器**：先面对固定脚本学习，再进入历史对手池自博弈，优化何时保持、防守或攻击。

自博弈时，每个对手在单局中保持冻结。周期性保存训练方快照，从历史快照池与固定脚本中采样对手；不让双方在同一局中同步改变网络参数。仅对阵最新对手作为消融，检查历史池是否缓解遗忘或策略循环。训练期间与评估期间的对手池分离，评估不更新网络或归一化统计。

奖励以有效得失分与终局结果为主，可加入小幅动作变化/能耗惩罚；不将剑速越大或碰撞力越大作为主要奖励。第一版不依赖人工设计复杂的“成功格挡”奖励，避免通过反复擦剑刷分。固定回合长度，并检查是否出现永远 Guard、乱刺或利用碰撞穿透等策略漏洞。

## 7. 公平评估与消融

主要结果是同一技能能力下的调度差异，不推断某种武术体系优于另一种，也不将动画数据质量与 RL 调度收益混为一谈。

评估计划包括：

1. 随机、脚本、PPO 三类策略在相同初始状态和配对随机种子下对战，交换场地角色，报告胜/负/平、净得分、非法接触和失败比例。
2. 使用训练未覆盖的脚本时序、等待时间或经过验收的执行速度组合，评估泛化；这些变化仍须保持在已验证工作空间和执行边界内。
3. 历史对手池 vs 仅最新快照的至少一项消融；两者保持相同训练环境步数预算及模型设置，并报告实际墙钟时间。
4. 目标为至少 3 个独立训练种子；冻结 checkpoint 后用独立评估种子运行多回合，保存每个训练种子的结果、回合数与统计不确定性。不把同一模型的大量回合冒称为独立训练重复。若预算不足，报告实际数量和限制，不补造显著性。

除胜率外，报告每回合有效攻击次数、被命中率、时间/回合长度、实际关节跟踪误差、最大速度和实际执行器力矩。防守能力应通过是否减少被命中来检验，不能仅以选过 ParryUp 或发生剑剑碰撞来证明。

## 8. 现有证据与尚未完成事项

### 2026-11-22 补充：落地单臂第一轮实装动作匹配

根据团队最新范围，不再构建人形躯干：原 CAD 底架以原朝向固定于地面，仅整体上移 8 mm；机械臂、横向近护手夹具和 1.08 m shinai 均不缩放。采用实际 `shinai_grip` 与 `shinai_tip`，握点至剑尖为 0.79 m。原 XML/网格和 CAD 质量惯量保持不变。

在同一固定工具空间映射、已有 0.5 握点位移适配和**假设各关节 ±π**的条件下，保留全部 128 帧 Stab、58 帧 ParryUp，并增加帧间插值后，509/509、229/229 个目标符合握点 2 cm、剑轴 5°、剑尖 5 cm 的运动学验收阈值；实际最大握点拟合误差约为 0.100 mm、0.078 mm。这是相对适配参考的 IK 误差，不是实物定位精度。Guard 是同源第一帧构造的保持位，不是第三段独立捕获动作。原微小调试关节窗口无法匹配这些目标，真实机械限位仍未知。

另外完成独立的有限力矩真实步进慢放检查：保留源模型增益和原调试力矩上限，通过同一 position actuator 加模型重力前馈，不施加外部广义力或取消重力。逐段重新定时至目标速度上限 0.05 rad/s、目标加速度上限 0.1 rad/s²，Stab、ParryUp 分别完成 344.51 s、275.33 s 仿真；最大关节跟踪误差约 0.00582 rad、0.00363 rad，未触发代理穿透、力矩饱和或 MuJoCo 警告。

这仅支持“存在可拟合、在当前仿真假设下可极慢速闭环的候选参考”。源动画时序下关节峰速约 22.42/18.72 rad/s，不能直接用于执行；快动作的真实电机能力、机械耦合和限位、完整 CAD 碰撞仍未验证。检查直接 reset 到 Guard，未验证 CAD 零位到 Guard 的进入路径；也未加入对手、计分、格挡效果或策略训练。复现入口和输出解释见 [README 落地场景部分](../README.md#current-setup-floor-fixed-arm-and-first-ase-matching-test)。以下 11 月 21 日记录保留为历史阶段证据，不能与本轮新装配混用。

### 2026-11-21 阶段记录

截至 2026-11-21，原始仓库支持七个关节 J0–J6 的固定底座单臂模型加载；本地已有受限的 30 s 低速关节演示与自动化检查。原始 XML 未给出真实关节限位与执行器上限，机器人 geom 接触关闭，未包含剑、已标定夹具和双机计分环境。详见同目录 `model_status.md`；低速演示不证明攻防或实机可行。

ASE 的 Stab 和 ParryUp 共 63 个稀疏样本，在**移除 root 平移、握点位移缩放 0.5、特定紧凑工作区对齐、假想各关节 ±180°、假定握点/装配轴**的条件下，存在 63/63 通过既定静态 5D IK 误差阈值的配置。该诊断使用握点误差 2 cm、剑轴误差 5°、派生剑尖误差 5 cm 阈值。

这仅说明某组假设下这些抽样目标具有运动学适配的可能，不是完整片段、Guard、技能连接段、真实机构限位、碰撞、有限力矩或自博弈验收。对齐也不是独立 held-out 验证。**完整 ParryUp 的闭环执行与防守效果尚未通过验收。**文件或变量中的 `safe` 表示转换后的数值容器名称，不表示动作安全认证。

仍需团队确认：实际独立自由度与耦合、保守机械限位、输出侧力矩和速度、质量/惯量修正、握把夹具变换、shinai 质量与质心/惯量、双方布局与计分规则。现有照片读数可暂记录为约 0.436 kg，总长约 1.08 m，柄长约 0.32096 m，质心约距柄尾 0.50 m；测量与安装基准须复核。这些数值不能单独确定完整惯性张量。

## 10. 工具、复现与许可

主工具为 Python、MuJoCo、NumPy/SciPy，以及选定的 PPO 实现（如 Stable-Baselines3/PyTorch，实施时锁定版本）。离线 IK 与数据转换保留源代码和配置，不依赖上游训练代码执行。Git/GitHub 用于版本与实验配置追踪。

Plan 1 的复现材料应包含：源文件 URL 与 SHA-256、许可说明、受限数据转换器、技能清单及 Guard 定义、机器人与工具变换、缩放/滤波/时间重采样参数、IK 约束、闭环验收日志、环境版本、随机种子、训练预算、checkpoint 与逐回合评估结果。需提供真实可运行的命令后再标为完成，不将此清单视为现成训练入口。

本分支已提供[技能库使用说明](../motion_skills/plan1/README.md)、[固定版本来源清单](../motion_skills/plan1/manifest.json)和 `python -m plan1_skills` 工具，可下载、校验、生成与采样三项工具空间参考模板。这些入口不执行机器人 IK、动力学回放或 PPO；完整训练命令尚不存在。Guard 在当前生成器中明确取 Stab 的第一帧作为候选保持姿态，不代表该姿态已经标定到机器人。

不直接提交第三方 motion 原文件或其大体量衍生轨迹到本仓库。采用校验 SHA-256 的按需下载与本地转换；下载结果和生成轨迹保持在忽略目录。使用方自行遵守数据许可，不能因为代码可获得就推断动作数据无限制可再分发。

## 11. 预期结果与结论边界

预期交付是一套可复现的双固定机械臂仿真、经过逐项验收的少量数据参考技能、随机/脚本/PPO 调度对照、至少一项消融及诚实的失败分析。可检验的假设是自博弈调度改善特定对手与时序下的净得分，而不是预先承诺某个胜率。

本方案保留运动、力矩和接触日志来发现不合理行为，但仿真数值稳定、低速跟踪或 IK 通过均不等于硬件可执行或人机接触无害。弹簧、阻抗控制或识别标记本身也不能构成“保证无害”的证据。最终报告限于教育/体育场景中的仿真研究，同时简要讨论机器人对抗的双重用途、数据权利和实机部署所需的额外验证，不将这些未完成的验证写成既有能力。
